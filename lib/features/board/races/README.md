# 대회 화면의 설계 근거

이 화면의 목표는 대회 날짜·장소·접수 상태를 비교하고 공식 사이트로 이동하는 것입니다. 모든 사용자에게 가장 좋은 형태가 입증된 것으로 해석하지 않으며, 아래 연구 결과를 모바일 대회 탐색 화면에 적용한 설계입니다.

## 연구와 적용 범위

- Rosenholtz, Li, Nakano(2007), 「Measuring visual clutter」: 시각적 혼잡과 탐색의 관계를 연구했습니다. 날짜·제목·장소·상태의 위치를 일정하게 하고 장식과 강조색의 수를 줄이는 근거로 참고했습니다. [저자 연구실 설명](https://persci.mit.edu/research/clutter), [논문](https://doi.org/10.1167/7.2.17)
- Tuch 등(2012), 「The role of visual complexity and prototypicality regarding first impression of websites」: 낮은 복잡도와 높은 전형성이 웹사이트의 미적 첫인상 평가에 유리했습니다. 이 결과를 익숙한 목록·선택 메뉴·상세 정보 구조에 참고했습니다. 웹사이트의 첫인상 연구이므로 앱의 만족도·전환율이 향상됐다고 단정하지 않습니다. [연구자 제공 자료](https://research.google.com/pubs/pub38315.html)
- [WCAG 2.2 글자 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum): 일반 글자 대비 4.5:1 이상을 기준으로 삼았습니다. [확장 터치 영역 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)은 44×44 CSS 픽셀 이상입니다. Flutter에서는 주요 선택·검색·외부 이동 제어의 최소 높이를 48 논리 픽셀 이상으로 잡았습니다. 이 수치만으로 앱 전체 WCAG 준수를 주장하지 않습니다.

## 구체적인 설계 판단

- 기본 화면은 흰색이며 보조 글자는 `#596574`입니다. 흰색 대비는 약 5.93:1입니다.
- 상태는 색과 별개로 항상 글자로 표시합니다. 모집중만 옅은 파랑으로 강조하고 다른 상태는 중립색으로 표시합니다. 파란 상태 글자의 배경 대비는 약 4.82:1, 회색 배지는 약 5.49:1입니다.
- 가로로 잘리던 상태 선택지는 한 메뉴에서 모두 보여줍니다. 선택한 조건과 검색 결과 개수는 목록 위에 남깁니다.
- 연도·월별로 묶어 날짜를 비교하기 쉽게 합니다. 제목·장소·상태는 같은 위치에서 읽도록 정렬합니다.
- 상세는 일정·장소·접수, 참가비, 소개 순으로 묶습니다. 공식 사이트 이동은 하단의 한 버튼으로 제공합니다. 버튼의 흰 글자와 파란 배경 대비는 약 5.41:1입니다.
- 320×740 논리 픽셀, 200% 글자 확대에서 필터·상세의 레이아웃과 조작을 검증합니다. 운영체제 글자 확대를 제한하지 않습니다.

## 검증과 한계

`test/marathon_board_test.dart`에서 상태 선택·상세 이동·검색·실패 복구·글자 확대·상태 배지 대비를 검사합니다. 실제 시뮬레이터에서도 목록과 상세 화면을 확인합니다. 사용자 만족도나 탐색 속도의 개선은 별도의 사용자 테스트가 필요합니다. 후속 비교에서는 같은 대회의 접수 상태를 찾는 시간, 잘못 누른 횟수, 정보 회상 정확도를 측정하는 것이 적절합니다.

# 게시판 화면의 공통 설계

동네·전국·러닝 대회 목록, 글 작성·수정, 글 상세·댓글, 동네 선택과 신고 화면에 `BoardTheme`를 적용합니다. 다른 앱 탭의 기본 테마와 서버의 공개·작성·관리 권한은 변경하지 않습니다.

## 근거와 적용

- Tuch 등(2012)의 [시각적 복잡도·전형성 연구](https://research.google/pubs/the-role-of-visual-complexity-and-prototypicality-regarding-first-impression-of-websites-working-towards-understanding-aesthetic-judgments/)는 복잡도가 낮고 익숙한 웹사이트 구조가 미적 첫인상 평가에 유리함을 보여줍니다. 게시판에는 익숙한 목록→상세→댓글 흐름과 일정한 필터·검색 위치로 적용했습니다. 웹사이트의 첫인상 결과를 앱의 장기 만족도나 참여율 향상이 입증된 것으로 해석하지 않습니다.
- Rosenholtz 등(2007)의 [시각적 혼잡 연구](https://persci.mit.edu/research/clutter)는 과도한 시각 요소와 탐색의 관계를 다룹니다. 글 제목·작성 정보·행동 버튼을 구분하고, 장식·중복 테두리·여러 강조색을 줄이는 데 참고했습니다.
- [WCAG 글자 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)의 일반 글자 4.5:1을 기준으로 공통 색상 조합을 검증합니다. [확장 터치 영역 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)을 참고해 주요 버튼은 48 논리 픽셀 이상, 사진 제거는 44 논리 픽셀 이상으로 설계했습니다. 앱 전체의 WCAG 준수를 의미하지는 않습니다.

## 공통 규칙

- 배경은 흰색, 본문은 진한 회색, 보조 정보는 `#596574`, 주요 동작은 파란색 `#1B64DA`입니다. 좋아요의 빨간 하트와 오류 안내는 의미가 있는 예외입니다.
- 제목 24, 구획 제목·목록 제목 16, 본문 15, 작성 정보 12 논리 픽셀을 기본으로 사용합니다. 숫자 자체가 논문에서 입증된 최적값이라는 뜻은 아니며 읽는 역할에 따른 구현 기준입니다. 운영체제의 글자 확대는 제한하지 않습니다.
- 목록 필터는 왼쪽의 `BoardFilterMenu`, 검색은 오른쪽에 배치합니다. 말머리와 접수 상태는 같은 메뉴 구조를 사용하며 선택한 조건이 항상 보입니다.
- 말머리와 접수 상태는 같은 `BoardLabel`로 표시합니다. 텍스트를 함께 보여 색상만으로 의미를 전달하지 않습니다.
- 글 상세는 제목→작성 정보→본문·사진→반응→댓글 순서입니다. 본문은 보통 굵기, 제목은 굵게, 날짜·작성자는 작고 충분한 대비로 구분합니다.
- 입력란·버튼·대화상자의 모서리와 색을 통일합니다. 작성 화면의 말머리는 입력 항목이므로 선택 칩을 유지하고, 목록의 탐색 조건은 공통 메뉴를 사용합니다.
- 댓글·답글의 연결과 들여쓰기는 유지합니다. 답글·삭제는 키보드와 화면 읽기에서 조작할 수 있는 버튼을 사용합니다.
- 320×740 논리 픽셀·200% 글자 확대에서 목록 필터, 상세 답글, 작성·등록, 사진 첨부 영역의 줄바꿈을 검증합니다.

## 검증과 한계

`test/board_ui_test.dart`와 기존 게시판·댓글·대회·신고 테스트를 함께 실행합니다. 실제 시뮬레이터에서 목록·상세·작성·신고 화면도 확인합니다. 모든 사용자에게 가장 보기 좋은 UI라고 단정할 수는 없습니다. 사용자 테스트에서는 원하는 글·접수 상태를 찾는 시간, 잘못 누른 횟수, 글 작성 완료율, 읽기 편안함을 같은 과제로 비교하는 것이 적절합니다.

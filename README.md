# 런스팟

실시간 지도에서 내 위치와 주변 러너를 확인하는 플러터 기반 러닝 앱입니다.

## 앱 개요

홈 화면은 실제 지도를 표시합니다. 위치 권한을 허용하면 내 위치를 표시하고 이동에 따라 갱신합니다.
코스 생성·프리셋 추천 기능은 제거했습니다.

## 주요 기능

- 내 현재 위치와 주변 러너 지도, 내 위치로 이동
- 현재 위치 기준 날씨·미세먼지 관측값과 러닝 환경 참고 판단
- 프로필의 러닝 시 위치 공유 설정, 측정 중 자동 공유 및 러너 닉네임·거리 확인
- 러닝 종료 시 개인 기록·경로 저장, 내 기록 목록과 상세 지도, 날짜·거리·시간·평균 페이스 조회
- 완료 기록의 기기 보관, 앱 재실행 후 복구 및 서버 저장 자동 재시도
- 러닝 중 화면 꺼짐·백그라운드 전환에도 개인 거리·시간 측정 유지
- 러닝 중 현재·평균 페이스와 지도 위 지나온 경로 표시
- 소셜의 친구 목록, 정확한 닉네임 검색, 친구 요청·수락·거절·취소·삭제
- 비공개·친구 공개·전체 공개와 차단을 반영한 서버 조회
- 프로필 개인 통계·친구 주간 거리 랭킹·업적은 서버 저장 기록을 집계합니다. 관리 화면은 실제 이상 기록과 승인·반려 처리를 제공합니다.

홈의 러닝 시작·일시 정지·계속·종료 버튼으로 현재 러닝의 거리와 시간을 측정합니다.
측정 화면 아래에 거리·시간·현재 페이스·평균 페이스를 표시합니다. 현재 페이스는 GPS 시각과 누적 이동 거리의 최근 약 20초 구간을 사용하며, 5초·10m 이상의 표본이 쌓인 뒤 표시합니다. 최근 이동 또는 GPS 응답이 15초 넘게 없으면 `--:--`로 표시합니다. 평균 페이스는 일시 정지를 제외한 전체 측정 시간과 누적 거리로 계산합니다.
지나온 경로는 지도에 녹색 선으로 표시하며 GPS 오차 수준의 흔들림·중복 위치는 제외합니다. 일시 정지·부정확한 위치·30초 넘는 위치 단절 뒤에는 새 선으로 시작하여 미측정 구간을 연결하지 않습니다. 종료 시 구간별 좌표를 기록과 함께 보관하고 본인 전용으로 서버에 저장합니다.
프로필의 `러닝 시 위치 공유`에서 자동 공유 여부를 계정별로 저장합니다. 기본값은 꺼짐이며 홈에서는 공유 상태만 표시합니다. 설정을 켜 두면 정확한 GPS로 러닝 시작·재개가 완료될 때 자동 공유하고 일시 정지·종료·백그라운드 전환 시 공유를 중단합니다. 앱으로 복귀해 러닝이 계속 중이면 저장된 켜짐 설정에 따라 다시 공유합니다. 이메일 인증·닉네임·친구 또는 전체 공개 조건은 그대로 적용하며 이 설정이 공개 범위를 변경하지 않습니다. 전송 중 중단한 경우에도 삭제 요청이 늦은 전송 뒤에 실행되도록 직렬화합니다. 설정을 끄면 서버 저장 응답보다 먼저 전송을 중단하며 저장·조회 실패 시 공유를 끄고 재시도를 제공합니다. 설정 조회가 지연되거나 실패해도 개인 러닝은 비공개로 시작할 수 있습니다.
종료 시 위치 공유를 중단하고 개인 기록을 저장한 뒤 결과를 표시합니다. 러닝 중 화면이 꺼지거나 앱이 백그라운드로 가도 개인 측정은 계속됩니다. 일시 정지·종료 또는 GPS 오류 시 백그라운드 측정을 해제하며, GPS 오류 뒤에는 계속 버튼으로 재개합니다.
하단 `프로필` 탭의 `내 기록` 항목 또는 종료 결과의 `내 기록` 버튼으로 목록을 엽니다. 최신 순으로 20개씩 표시하고 새로고침·더 보기·기록 상세를 제공합니다. 기록을 누르면 전체 경로 지도와 출발·도착 표시를 볼 수 있습니다. 경로가 저장되지 않은 기존 기록에는 경로 없음 상태를 표시합니다. 홈 상단 바와 조회 반경 선택은 제거하고 주변 러너는 기본 반경 1km로 조회합니다.
완료 기록은 서버 요청 전에 기기의 SQLite 저장소에 먼저 보관합니다. 서버 연결 실패 시 결과에 `기기에 저장됨`, 목록과 상세에 `서버 저장 대기`를 표시하며 다음 러닝을 시작할 수 있습니다.
로그인 후 앱 시작·복귀, 목록 새로고침과 `저장 재시도`에서 미전송 기록을 복구합니다. 앱이 열려 있는 동안 연결 실패는 30초부터 최대 5분 간격으로 자동 재시도하며, 백그라운드에서는 새 재시도 요청을 시작하지 않습니다. 서버가 측정값·권한·설정 문제로 거부한 기록은 원본을 유지하고 자동 반복 전송은 중단합니다.
서버가 성공 응답을 보낸 뒤에만 기기의 대기 원본을 삭제합니다. 응답 중단·삭제 실패·앱 종료 후에도 동일한 식별자와 측정값을 재전송하여 서버의 사용자별 중복 방지를 사용합니다.
보관 기록은 서버 주소와 계정별로 분리합니다. 로그아웃 시 원본은 보존하고 같은 계정으로 다시 로그인해야 조회·전송합니다. 저장소에는 완료 시각·거리·시간·기록 식별자와 구간별 위도·경도를 보관하며 인증 토큰이나 위치 정확도·좌표별 시각은 저장하지 않습니다. 저장소는 Android·iOS 앱 전용 영역을 사용하며 별도 데이터베이스 암호화는 적용하지 않습니다. 기록과 경로가 서버에서 함께 확정된 뒤에만 전송 대기 원본을 삭제합니다.
기기 저장 자체가 실패하면 종료 결과를 메모리에 유지하고 홈의 `저장 재시도`로 다시 저장해야 합니다. 이때 앱을 종료하면 결과를 잃을 수 있습니다. 진행 중 러닝은 별도의 기기 저장소에 보관하며 아래 복구 정책을 따릅니다. 전체 서버 기록의 오프라인 캐시는 포함되지 않습니다. 앱 삭제 또는 기기 데이터 삭제 시 기기에만 남은 기록은 복구할 수 없습니다.
서버 경로는 상세를 열 때만 조회하며 친구나 다른 사용자에게 공개하지 않습니다. 전송 대기 기록의 경로는 오프라인에서도 볼 수 있지만 지도 배경은 연결 또는 타일 캐시가 필요합니다. 서버 저장을 마친 경로의 오프라인 캐시는 포함되지 않습니다. 서버 검증 전 측정값은 랭킹이나 공개 게시물로 자동 반영하지 않습니다. 소셜의 함께 달리기에서 친구 초대·공동 출발·그룹 결과 비교를 제공합니다.

## 러닝 환경

홈의 지도 아래에는 기온·강수 상태·초미세먼지 참고 등급과 `양호`, `주의`, `자제`, `판단 불가` 상태를 표시합니다. 오른쪽 상세 버튼으로 바람·미세먼지 두 항목의 원래 관측 농도·측정소 거리·관측 시각·출처를 확인합니다. 보안등과 코스 추천은 반영하지 않습니다.

기상청 초단기실황과 한국환경공단 에어코리아 관측 자료를 Supabase `running-conditions` 함수에서 조회합니다. 인증키는 서버의 `KMA_SERVICE_KEY`, `AIRKOREA_SERVICE_KEY`에만 등록하며 앱 기능은 공공데이터 키를 참조하지 않습니다. 기상청 단기예보·에어코리아 대기오염정보·에어코리아 측정소정보 서비스의 활용 승인이 모두 필요합니다. 서버 설치와 검증 명령은 `supabase/README.md`를 참고합니다.

앱은 약 1km로 반올림한 위치만 서버에 보내며 외부 기관에는 기상청 5km 격자 또는 측정소 이름만 전송합니다. 위치를 환경 조회 이력으로 저장하지 않습니다. 두 미세먼지 항목을 측정하는 가장 가까운 측정소를 선택하되 30km를 넘으면 자료 없음으로 표시합니다. 국내 제공 범위 외에는 지원하지 않습니다.

홈이 보이는 동안 5분 주기로 서버 자료를 확인하며 위치 구역 변경 시 자동 조회합니다. 자동 재조회는 1분, 수동 재조회는 10초 이상 간격을 둡니다. 외부 API는 사용자마다 호출하지 않습니다. 날씨는 같은 5km 격자·발표 시각의 자료를 공동 사용하고, 미세먼지는 시·도 측정소 자료를 한꺼번에 받아 한 시간 동안 공유합니다. 현재 위치에는 가장 가까운 측정소의 농도를 표시하며 지역 평균으로 대체하지 않습니다. 조회 요청이 없는 지역은 갱신하지 않습니다.

서버 전체에서 기관별 최근 24시간 최대 450회의 외부 호출을 예약·집계합니다. 실패·시간 초과·추가 페이지도 포함하며 같은 지역 동시 요청은 하나의 갱신 작업만 수행합니다. 한도나 장애가 발생하면 마지막 정상 자료와 관측 시각·갱신 실패 안내를 표시합니다. 이 앱 서버 외부에서 같은 인증키를 사용하는 호출은 집계할 수 없으므로 키의 다른 사용처와 공공데이터포털 이용량도 확인해야 합니다.

다른 탭이나 백그라운드에서는 새 환경 조회를 시작하지 않으며 러닝 측정에는 영향을 주지 않습니다. 결측·기관 장애·공동 갱신 실패·관측 2시간 경과·잘못된 시각은 정상 자료로 대신하지 않고 전체 양호 판단을 중단합니다. 일부 정상 자료에서 주의 조건이 확인되면 해당 주의와 자료 누락을 함께 표시합니다.

기온 0°C 이하·30°C 이상, 풍속 8m/s 이상, 강수 관측은 앱 자체의 참고 주의 기준입니다. 두 미세먼지 농도 중 더 나쁜 참고 등급을 반영하며 매우 나쁨에는 야외 러닝 자제를 표시합니다. [에어코리아 농도 구간](https://m.airkorea.or.kr/info/behaviorInfo1)을 사용하지만 시간별 관측 농도의 참고 분류이며 공식 일평균 예보·특보나 건강 안전 보장이 아닙니다.

## 친구 관리

- 하단 `소셜`의 `친구`, `요청`, `검색` 탭에서 관리합니다. 실제 친구 주간 거리 비교는 `랭킹` 탭에서 확인합니다.
- 친구 검색·요청·수락은 이메일 인증과 닉네임 등록 후 가능합니다. 미인증 상태에서도 기존 개인 친구 목록 조회·요청 취소·거절·친구 삭제는 가능합니다.
- 검색은 정확한 닉네임 하나로 하며 영문 대소문자는 구분하지 않습니다. 본인, 신규 비공개 대상, 미인증·정지·양방향 차단 계정은 검색하지 않습니다. 검색과 요청 목록에는 이메일·전화번호·좌표를 반환하지 않습니다.
- 비공개 사용자가 공개된 상대에게 요청하면 그 상대에게 요청자의 닉네임이 표시됩니다. 친구 수락이나 삭제는 공개 범위와 러닝 시 위치 공유 설정을 바꾸지 않습니다.
- 요청은 받은 사람만 수락·거절할 수 있습니다. 서로 요청해도 자동으로 수락하지 않으며, 이전 요청의 화면으로 새 요청을 취소하거나 수락하지 못하도록 관계 식별자를 검사합니다.
- 새 요청은 5초 간격, 계정당 한 시간에 30번으로 제한합니다. 친구와 양방향 대기 요청 합계는 계정당 최대 500개입니다. 취소·거절·삭제는 확인한 서버 상태를 기준으로 처리합니다.
- 소셜 화면을 열거나 앱으로 복귀할 때, 새로고침과 변경 후 서버 상태를 조회합니다. 소셜 화면이 열려 있는 동안 30초마다 갱신하며 백그라운드 조회와 푸시 알림은 포함하지 않습니다.
- 서버에는 `supabase/migrations/20261009100450_friend_management.sql`이 필요하며 연결된 RunSpot 프로젝트에 적용했습니다. 함께 달리기 초대는 친구 요청과 별개이며 수락된 친구만 초대할 수 있습니다.

## 개인 통계와 친구 랭킹

서버 마이그레이션 `20261020065459_run_statistics_and_friend_ranking.sql`이 필요합니다. 로컬 검증과 연결된 RunSpot 서버 반영을 완료했습니다.

- 프로필의 이번 주 거리는 한국 시간 월요일 00시부터 다음 월요일 00시 전까지 종료한 기록으로 계산합니다. 미래 종료 시각의 기록은 해당 시각이 지난 후 반영합니다.
- 완료 러닝 수는 전체 누적 기록 수입니다. 평균 페이스는 거리와 활동 시간이 모두 양수인 전체 기록의 총 활동 시간 ÷ 총 거리로 계산하며, 기록별 페이스를 단순 평균하지 않습니다. 유효한 이동 기록이 없으면 `--:--`를 표시합니다.
- 서버 저장 완료 기록만 집계하며 기기에만 보관된 기록은 전송 완료 뒤 반영합니다. 기록 목록의 페이지 수와 무관하게 서버에서 전체 기록을 집계합니다.
- 소셜의 랭킹은 본인과 수락된 친구의 주간 거리 내림차순입니다. 같은 거리는 공동 순위이며 다음 순번은 건너뜁니다. 거리 0인 친구도 표시합니다. 성장·5K·꾸준 순위의 예시 탭은 제거했습니다.
- 본인은 비공개여도 자기 순위를 확인할 수 있습니다. 친구는 이메일 인증·활성 계정·닉네임·친구 관계·프로필 공개 범위·양방향 차단을 서버에서 확인합니다. 비공개·미인증·정지·차단·미수락·친구가 아닌 대상은 제외합니다.
- 개인 통계는 저장된 모든 완료 기록을 집계합니다. 친구 거리 비교는 `rejected` 기록을 제외하며 `pending` 개인 측정 기록도 포함합니다. 검증 완료된 공식 경쟁 순위가 아니며 서버가 기록 상태를 변경하지 않습니다.
- 개인 통계와 랭킹은 화면 진입·앱 복귀·30초 간격·수동 새로고침으로 갱신합니다. 친구 목록 갱신 뒤에도 랭킹을 재조회합니다. 백그라운드에서는 자동 조회를 중단하며 조회 실패 시 이전 랭킹을 남기지 않고 재시도를 제공합니다.
- 타인의 기록·경로·개별 러닝 시각은 공개하지 않습니다. 랭킹에는 닉네임·합계 거리·순위·본인 여부만 반환합니다.

## 실행 방법

```sh
flutter run --dart-define-from-file=config/dev.json
```

`config/dev.json`에는 Supabase URL과 공개 키가 들어 있어야 합니다. 새 환경에서는 `config/example.json`을 복사해 실제 값을 채운 뒤 실행합니다.
디버그 IO 환경에서는 앱이 `config/dev.json`을 자동으로 보완 로딩하지만, 웹 실행이나 배포 빌드에서는 위 실행 옵션처럼 빌드 설정을 명시해야 합니다.
Supabase Auth의 Redirect URLs에는 `runspot://login-callback`을 등록해야 이메일 확인과 소셜 로그인이 앱으로 돌아옵니다.

## 러닝 기록 SNS 공유

- 러닝 종료 결과창의 `공유` 또는 `프로필 → 내 기록 → 기록 상세 → 공유 아이콘`에서 전체 화면 미리보기를 확인하고 상단 공유 아이콘으로 휴대폰 공유창을 엽니다. PNG 너비는 1080px이며 높이는 휴대폰 화면 비율을 따릅니다(1512~3240px, 가로·큰 화면에서도 세로형 유지). 실제 게시·전송은 사용자가 선택한 앱에서 완료합니다. 종료 결과의 기본 측정값과 경로는 서버 저장 대기 중에도 공유할 수 있습니다.
- 이미지에는 거리·시간·평균 페이스·종료 시 기온과 사용자가 선택한 경로 선만 표시합니다. 기온이 없는 기록은 `--`로 표시하며 값을 추정하지 않습니다. 브랜드·제목·보호 구역 안내 문구·AI 피드백·이메일·전화번호·닉네임·식별자·날짜·주소는 이미지에 넣지 않습니다.
- 상단 `공유 설정` 아이콘의 설정 패널에서 밝은 배경·어두운 배경·갤러리 사진 한 장과 경로 포함 여부를 선택합니다. 기본 배경을 누르면 사진을 제거하며, 사진 선택 취소·실패 시 기존 배경을 유지합니다. 선택 사진은 중앙을 기준으로 채워지고 글자가 읽히도록 명암을 조정합니다.
- 글자 색은 자동·흰색·검정·라임·하늘·노랑·분홍 견본 또는 사용자 지정 색상 코드·빨강/초록/파랑 슬라이더로 선택합니다. 잘못된 코드는 적용하지 않으며 취소하면 기존 색을 유지합니다. 선택 색은 미리보기와 공유 PNG에 동일하게 반영하며 서버에 저장하지 않습니다.
- 사진과 숫자 요약을 함께 공유하는 [Nike Run Club](https://www.nike.com/help/a/nrc-share/nrc-activity)·[Strava](https://support.strava.com/en-us/articles/15401840-sharing-your-strava-activities)의 흐름을 참고해 큰 거리 숫자, 별도 거리 단위, 값 중심의 시간·페이스·기온 행을 중앙 정렬했습니다. 사진 명암은 55%로 유지하되 밝은 글자에는 검정, 어두운 글자에는 흰색 막을 적용하고 낮은 대비는 얇은 윤곽선으로 보완합니다.
- 사진은 서버에 업로드하지 않습니다. 전체 갤러리나 사진 메타데이터 접근을 요청하지 않고 선택한 사진의 픽셀만 PNG로 합성합니다. 원본 사진의 위치 메타데이터는 PNG에 복사하지 않지만 사진 자체에 보이는 얼굴·장소·문구는 공유됩니다. Android가 사진 선택 중 앱을 종료하면 재실행 시 복구 대기 선택을 비우고 사용자가 다시 선택하도록 하며, 다른 계정·기록에 자동 연결하지 않습니다.
- 선택한 파일은 20MB 이하이며 디코딩 시 긴 변을 최대 2048px로 제한합니다. iOS 시뮬레이터의 HEIC 선택은 플랫폼 제한이 있으므로 해당 형식은 실기기에서 확인해야 합니다. [image_picker 공식 안내](https://pub.dev/packages/image_picker)
- 경로 포함은 위치 유추 위험을 확인한 뒤 선택합니다. 지도 배경·좌표·출발/도착 표식 없이 전체 이동 경로의 선 모양만 그립니다. 일시 정지·긴 GPS 간격은 연결하지 않으며 300m 같은 짧은 기록도 표시합니다. 정지 기록에는 공유할 선이 없습니다.
- 공유 화면의 AI 피드백 포함 기능은 제거했습니다. 기록 상세의 기존 AI 피드백 생성·조회 기능은 유지하며 공유 화면에서는 피드백 조회·생성을 하지 않습니다.
- 공유는 본인 계정에서만 가능하며 계정 변경 시 미리보기를 숨깁니다. 전송 대기 기록의 기본 측정값과 기기 경로도 공유할 수 있습니다.
- 공유 PNG는 앱 전용 임시 캐시에 보관합니다. 취소·실패 시 미전송 파일을 삭제하고, 정상 전달한 파일은 수신 앱의 지연 읽기를 위해 유지합니다. 다음 공유에서 24시간 지난 이 기능의 캐시만 정리합니다. 서버·DB·위치 공개 설정은 변경하지 않습니다.
- iPhone 시뮬레이터에서 PNG 미리보기와 실제 공유창을 확인했습니다. Instagram·카카오톡 등 개별 앱의 수신·게시와 Android 실기기 전송은 별도 확인이 필요합니다. 이미지 공유는 상대 앱 지원에 따라 다릅니다. [share_plus 공식 안내](https://pub.dev/packages/share_plus)
- 종료 직후 공유 추가 후 앱 테스트 204개와 관련 코드 정적 검사가 통과했습니다. 정상 저장·오프라인 종료 결과에서 공유 화면 이동·서버 기록 식별자·홈 복귀와 기존 PNG 렌더링·개인정보 기본 제외·보호 경로·저장된 피드백만 조회·중복 실행·취소·오류 재시도·계정 전환·작은 화면을 검증했습니다.
- 전체 화면 공유 변경 후 앱 테스트 214개와 관련 코드 정적 검사가 통과했습니다. 휴대폰 화면 비율·전체 화면 미리보기·배경 선택·보호 경로·AI 피드백 옵션 제거·공유창 취소·계정 전환·종료 후 공유 및 홈 복귀를 확인했습니다. 기록 상세의 AI 피드백 기능과 서버·DB는 변경하지 않았습니다.
- 중앙 정렬·글자 색 편집 추가 후 앱 테스트 218개와 관련 코드 정적 검사가 통과했습니다. 색상 코드 검증·색상 채널 연동·자동 복원·PNG 색상 픽셀·낮은 대비 윤곽선과 작은 화면 색상 선택 창을 검증했습니다.

### 종료 시 기온

- 종료 위치 구역에 맞는 최근 기상청 관측 기온과 원래 관측 시각을 기록에 고정합니다. 종료 시각 기준 2시간보다 오래되거나 15분을 초과해 미래인 관측, 부정확하거나 오래된 위치, 다른 구역의 자료는 저장하지 않습니다. 기존 기록은 `자료 없음`으로 유지합니다.
- 종료 시 날씨 API를 추가 호출하지 않습니다. 홈의 지역별 공동 캐시 자료를 사용해 기존 조회 예산을 유지합니다. 기온은 기기 저장·오프라인 재전송 후에도 바뀌지 않으며 기록 상세와 종료 결과에서 관측 시각을 확인할 수 있습니다.
- 기온은 개인 기록 참고 자료이며 실제 기기 온도나 검증된 경기·랭킹 자료가 아닙니다. 서버 저장에는 `20261013012622_run_temperature_snapshot.sql`이 필요합니다.
- iPhone 시뮬레이터에서 기존 기록의 `자료 없음`, 기본 갤러리 사진 선택·PNG 합성 및 실제 공유창의 사진 배경을 확인했습니다. 외부 SNS 전송이나 Android 실기기 선택은 검증하지 않았습니다.
- 기온·갤러리 배경 추가 후 앱 전체 테스트 216개, SQL 테스트 13개와 기온 동시 저장 테스트가 통과했습니다. 관련 코드 정적 검사와 iOS 권한 설정 검사를 완료했습니다.

## AI 러닝 피드백

- `프로필 → 내 기록 → 기록 상세`에서 사용자가 요청한 경우에만 Gemini 피드백을 생성합니다. 화면 진입과 상태 확인은 외부 AI를 호출하지 않습니다.
- 현재 기록의 거리·시간·페이스와 러닝 시작 전 30일 안의 최대 5회 숫자 요약을 비교합니다. 비교 기록이 없으면 그 한계를 안내합니다. 생성된 피드백은 본인만 반복 조회할 수 있습니다.
- 이메일 인증이 필요하며 서버에 저장된 거리 100m 이상·활동 시간 60초 이상의 완료 기록만 분석합니다. 저장 대기·이동 없는 기록은 생성 한도를 사용하지 않습니다.
- 계정별 요청은 최근 72시간에 1회입니다. 외부 호출 예약 후 실패하거나 응답을 받지 못해도 한도는 환불하지 않습니다. 다른 기록·기기·재설치·기록 삭제로 우회할 수 없습니다.
- `GEMINI_API_KEY`는 Supabase 서버 비밀값에만 등록합니다. 앱 설정에 키를 넣지 않습니다. 요청 전 전송 항목을 안내하며 이메일·전화번호·닉네임·기록 식별자·날짜·GPS 경로는 Google에 전송하지 않습니다.
- 경험치·보상·의료 진단에는 피드백을 사용하지 않습니다. 전체 호출 예산, 배포와 검증 안내는 `supabase/README.md`에 있습니다.

## 선택 전화번호 인증

- 프로필의 `전화번호 인증 (선택)`에서 본인 번호의 서버 인증 상태를 확인합니다. 소셜·위치 공유 권한은 기존 이메일 인증과 닉네임 기준을 유지합니다.
- 수동 인증된 테스트 계정은 앱에 다시 로그인하지 않아도 이 화면에서 `인증 상태 확인`으로 최신 상태를 읽습니다. 앱에 자동 인증 코드나 관리자 키를 넣지 않습니다.
- 문자 발송은 Supabase Phone 제공업체와 SMS 업체를 연결해야 사용할 수 있습니다. 현재 발송 설정은 비활성화 상태이며, 미연결 시 인증을 우회하지 않고 오류를 안내합니다.
- `supabase/migrations/20261011185117_optional_phone_verification.sql`의 상태 조회 RPC가 필요합니다. 수동 확인은 지정한 테스트 계정의 관리자 작업이며 실제 문자 수신 검증이 아닙니다.

## 지도와 위치 공유

- 홈과 기록 상세 지도는 카카오 공식 웹 지도 SDK를 `webview_flutter`로 표시합니다. Android x86·x64 가상 휴대폰에서도 네이티브 카카오 지도 SDK 없이 동작하는 방식입니다. Android 7(API 24) 이상과 iOS 13 이상이 필요합니다.
- 카카오디벨로퍼스에서 카카오맵을 활성화하고 **JavaScript 키**의 SDK 도메인을 등록합니다. `config/dev.json`의 `KAKAO_JAVASCRIPT_KEY`와 `KAKAO_MAP_ORIGIN`을 사용하며 네이티브·REST API 키로 대체할 수 없습니다. 키를 소스나 채팅에 넣지 않습니다.
- 로컬 개발용 SDK 도메인은 `https://localhost`입니다. 같은 주소를 `KAKAO_MAP_ORIGIN`과 카카오 JavaScript SDK 도메인에 등록하고 `flutter run --dart-define-from-file=config/dev.json`으로 실행합니다. 운영 빌드에는 등록한 실제 HTTPS 서비스 도메인이 필수이며 localhost는 거절합니다. Xcode로 실행하려면 먼저 `flutter build ios --config-only --dart-define-from-file=config/dev.json`으로 빌드 설정을 준비합니다.
- 카카오 SDK의 지도 로고·저작권 표시는 가리지 않습니다. 지도 영역 조회 시 카카오에 해당 지도 영역 정보가 전달되지만 닉네임·러닝 경로는 기기 웹뷰 안에서 표시하며 별도 검색·경로 API를 호출하지 않습니다.
- 러닝 시작 시 주변에 집중하도록 확대하고 내 위치를 추적합니다. 수동 이동 시 추적을 중단하며 내 위치 버튼으로 권장 배율과 추적을 복원합니다. 카카오 확대 수준은 정수이므로 이전 지도의 소수 배율과 완전히 같지는 않습니다.
- 위치 공유는 기본으로 꺼져 있습니다. 공유를 켜려면 이메일 인증, 닉네임 등록, 친구 또는 전체 공개 설정이 필요합니다. 이메일 변경 확인 중에는 비공개로 전환하며 재인증 후에도 자동 공개하지 않습니다.
- 서버에 `supabase/migrations/20261006000100_live_runner_map.sql`을 기존 마이그레이션 다음에 적용해야 주변 러너가 표시됩니다. 자세한 적용 안내는 `supabase/README.md`를 확인합니다.
- 기록 저장에는 `supabase/migrations/20261008000100_run_history.sql`을 적용해야 합니다. 기록은 이메일 인증 여부와 관계없이 로그인한 본인만 조회할 수 있습니다.
- 개인 경로 저장·조회에는 `supabase/migrations/20261009104713_private_run_routes.sql`도 적용해야 합니다. 기존 기록과 이전 버전 기기 저장소는 그대로 유지합니다.
- 앱이 백그라운드로 가거나 프로필에서 설정을 끄면 공유를 중단합니다. 앱으로 복귀할 때 러닝 중이고 저장된 공유 설정이 켜져 있는 경우에만 다시 공유합니다.
- 이동 시 최대 5초 간격으로 전송하고, 정지 상태에서도 15초마다 현재 위치를 갱신합니다. 2분간 갱신되지 않은 위치는 조회에서 제외됩니다.
- 비공개 실시간 채널에는 좌표나 사용자 ID를 보내지 않습니다. 변경 신호 수신 후 서버 조회를 통해 현재 권한을 다시 확인합니다.
- 에뮬레이터는 테스트 위치를 설정해야 현재 위치를 찾을 수 있습니다. 실제 두 기기에서 공유·이동·비공개 전환을 확인해야 합니다.
- 카카오맵 무료 쿼터 적용 앱인지 확인합니다. 앱 활성화 순서·사용량에 따라 유료 API 설정이 필요할 수 있으며 앱은 유료 설정을 자동으로 활성화하지 않습니다. [카카오맵 설정·쿼터 안내](https://developers.kakao.com/docs/ko/kakaomap/common), [웹 지도 SDK](https://apis.map.kakao.com/web/guide/), [Flutter 웹뷰](https://pub.dev/packages/webview_flutter)를 참고합니다. 이전 `MAP_TILE_URL`·`MAP_ATTRIBUTION` 설정은 더 이상 사용하지 않습니다.

## 테스트 방법

### 화면 꺼짐 측정

- Android는 앱 화면에서 러닝 시작 후 위치 유형의 포그라운드 서비스와 지속 알림을 사용합니다. 러닝 중에만 부분 실행 잠금을 유지하며 화면 자체를 켜 두지는 않습니다.
- iOS는 앱 화면에서 시작한 GPS 구독을 백그라운드에서도 유지하고 시스템 위치 사용 표시를 켭니다. 지도만 보는 동안에는 백그라운드 측정을 허용하지 않습니다.
- 두 플랫폼 모두 사용 중 위치 권한으로 시작하며 항상 허용 권한은 요청하지 않습니다. 개인 측정 중에도 백그라운드에서는 위치 공유와 새로운 기록 업로드 재시도가 중단됩니다.
- 러닝 시작 준비 중 앱을 닫으면 시작을 취소합니다. 위치 오류로 정지한 측정은 앱 복귀만으로 자동 재개하지 않습니다.
- 앱 강제 종료·시스템의 프로세스 종료 뒤에는 마지막 기기 저장 지점에서 일시 정지 상태로 복구합니다. GPS가 30초 이상 끊긴 구간의 이동 거리도 추정해 더하지 않습니다.
- 실제 iPhone·Android에서 시작 → 화면 잠금 후 이동 → 잠금 해제 후 거리·시간 증가 → 일시 정지·종료 후 위치 표시·알림 해제를 확인해야 합니다. 공유를 켜고 같은 순서로 확인했을 때 잠금 이후 서버 위치 갱신이 없어야 합니다.

설정 근거: [Android 위치 권한](https://developer.android.com/develop/sensors-and-location/location/permissions), [포그라운드 서비스 시작 제한](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [iOS 사용 중 위치 권한](https://developer.apple.com/documentation/corelocation/cllocationmanager/requestwheninuseauthorization%28%29).

## 실제 업적·러닝 복구·차단·그룹·관리

새 서버 마이그레이션 3개는 사용자의 명시적 승인 후 2026-10-21 연결된 RunSpot 프로젝트에 적용했습니다. 적용 이력과 운영 규칙은 `supabase/README.md`를 참고합니다.

- 대표 업적은 첫 이동 러닝 완료·누적 10회·누적 50km입니다. 서버 저장 완료, 거리·활동 시간이 모두 양수, 미래 종료 시각이 아닌 기록을 계산합니다. 달성일은 시간순 누적으로 목표를 처음 넘은 기록의 종료 시각이며, 반려·기록 삭제 시 진행률과 달성 여부를 다시 계산합니다. 이전 기록도 첫 조회에서 반영합니다. 정지 기록은 횟수에서 제외합니다.
- 진행 중 러닝은 시작·일시 정지·백그라운드 전환·종료 및 측정 중 5초 간격으로 SQLite에 보관합니다. 앱 재실행 시 계정·서버가 일치하는 러닝만 일시 정지 상태로 복구합니다. 마지막 보관 이후 최대 약 5초의 측정과 앱 종료 이후 미측정 구간은 포함하지 않습니다. 복구 후 계속하면 새 경로 구간을 시작합니다. 종료 저장 도중 중단되면 동일 식별자·종료 시각·측정값으로 저장을 재시도합니다. 기기 저장 실패는 화면에 표시하며, 앱 삭제·저장소 손상 시 복구를 보장하지 않습니다.
- 친구 목록·요청·검색 결과 및 주변 러너 선택 카드에서 차단할 수 있습니다. 프로필의 `차단한 사용자`에서 해제합니다. 차단 시 친구 관계와 요청을 삭제하며 해제해도 자동 복원하지 않습니다. 두 사용자가 참여한 대기·진행 그룹은 취소하고 개인 측정은 유지합니다.
- 소셜 상단 `함께 달리기`에서 그룹을 만들고 친구를 초대합니다. 방장 포함 최대 8명이며 초대 수락은 닉네임·완료 거리·시간 공유에 동의하는 동작입니다. 개인 경로·실시간 좌표는 그룹에 공개하지 않습니다. 위치 공유 설정은 별도로 적용됩니다.
- 참여자 모두 GPS 준비를 마치면 방장이 서버 기준 10초 뒤 출발을 예약합니다. 준비된 앱은 서버 시각과 단조 시계를 사용한 카운트다운으로 각자의 측정을 시작합니다. 네트워크와 운영체제 실행 지연으로 기기별 실제 시작에는 차이가 날 수 있습니다. 백그라운드 전환·GPS 실패·상태 조회 실패는 준비를 해제하며, 3초 넘게 놓친 출발은 자동 시작하지 않습니다. 이 경우 개인 러닝을 시작하거나 새 그룹을 만듭니다.
- 그룹 대기는 30분, 출발 후 진행 유효 시간은 24시간입니다. 그룹 생성은 시간당 5개, 친구 초대는 시간당 30회이며 한 번에 하나의 활성 그룹에 참여합니다. 활동 그룹은 2초, 그룹이 없으면 30초 간격으로 앱이 열린 동안 확인합니다. 최근 그룹 20개를 표시하며 푸시 알림은 포함하지 않습니다.
- 그룹 시작 연결이 서버에 확정된 러닝은 개인 기록 전송 완료 시 그룹 결과에 자동 연결됩니다. 기기 보관 기록의 전송이 지연되어도 같은 식별자로 연결합니다. 출발 연결 자체가 실패하면 개인 기록은 유지하지만 그룹 결과에는 포함되지 않을 수 있습니다. 각자 홈에서 일시 정지·종료하며 모든 참여자가 완료하면 그룹도 완료됩니다. 반려 기록의 측정값은 그룹 결과에서 제외합니다.
- 관리 화면은 평균 속도 6.5m/s 초과 기록을 검토 대상으로 만듭니다. 현재 서버 관리자·검토자 역할과 다중 인증이 모두 필요하며 본인 기록은 검토할 수 없습니다. 인증 앱 등록·6자리 코드 확인을 제공합니다. 역할 부여는 앱 밖의 신뢰된 운영 경로에서만 수행합니다.
- 승인 시 기록을 검증 상태로 전환하되 기존 경험치 지급 기준은 유지합니다. 반려 시 개인 기록·통계는 보존하고 친구 랭킹·업적·현재 경험치에서 제외합니다. 동일 결정을 재시도해도 이력이 중복되지 않으며 반대 결정으로 덮어쓸 수 없습니다. 처리 사유와 감사 기록을 같은 트랜잭션에서 보관합니다. GPS 위조를 완전히 판별하는 기능은 아닙니다.

실기기 검증: 두 계정의 초대 수신·동의·GPS 준비·공동 출발·각자 종료·그룹 결과, 예약 중 화면 잠금과 네트워크 단절, 강제 종료 후 계정별 복구, 관리자 인증 앱 등록과 승인·반려를 확인해야 합니다.

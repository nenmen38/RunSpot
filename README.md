# 런스팟

실시간 지도에서 내 위치와 주변 러너를 확인하는 플러터 기반 러닝 앱입니다.

## 앱 개요

홈 화면은 실제 지도를 표시합니다. 위치 권한을 허용하면 내 위치를 표시하고 이동에 따라 갱신합니다.
코스 생성·프리셋 추천 기능은 제거했습니다.

## 주요 기능

- 내 현재 위치와 주변 러너 지도, 내 위치로 이동
- 현재 위치 기준 날씨·미세먼지 관측값과 러닝 환경 참고 판단
- 위치 공유 켜기·끄기 및 러너 닉네임·거리 확인
- 러닝 종료 시 개인 기록·경로 저장, 내 기록 목록과 상세 지도, 날짜·거리·시간·평균 페이스 조회
- 완료 기록의 기기 보관, 앱 재실행 후 복구 및 서버 저장 자동 재시도
- 러닝 중 화면 꺼짐·백그라운드 전환에도 개인 거리·시간 측정 유지
- 러닝 중 현재·평균 페이스와 지도 위 지나온 경로 표시
- 소셜의 친구 목록, 정확한 닉네임 검색, 친구 요청·수락·거절·취소·삭제
- 비공개·친구 공개·전체 공개와 차단을 반영한 서버 조회
- 프로필, 소셜, 관리 화면은 유지하며 통계·랭킹·업적·관리 데이터는 기존 예시 데이터입니다.

홈의 러닝 시작·일시 정지·계속·종료 버튼으로 현재 러닝의 거리와 시간을 측정합니다.
측정 화면 아래에 거리·시간·현재 페이스·평균 페이스를 표시합니다. 현재 페이스는 GPS 시각과 누적 이동 거리의 최근 약 20초 구간을 사용하며, 5초·10m 이상의 표본이 쌓인 뒤 표시합니다. 최근 이동 또는 GPS 응답이 15초 넘게 없으면 `--:--`로 표시합니다. 평균 페이스는 일시 정지를 제외한 전체 측정 시간과 누적 거리로 계산합니다.
지나온 경로는 지도에 녹색 선으로 표시하며 GPS 오차 수준의 흔들림·중복 위치는 제외합니다. 일시 정지·부정확한 위치·30초 넘는 위치 단절 뒤에는 새 선으로 시작하여 미측정 구간을 연결하지 않습니다. 종료 시 구간별 좌표를 기록과 함께 보관하고 본인 전용으로 서버에 저장합니다.
종료 시 위치 공유를 중단하고 개인 기록을 저장한 뒤 결과를 표시합니다. 러닝 중 화면이 꺼지거나 앱이 백그라운드로 가도 개인 측정은 계속됩니다. 일시 정지·종료 또는 GPS 오류 시 백그라운드 측정을 해제하며, GPS 오류 뒤에는 계속 버튼으로 재개합니다.
하단 `프로필` 탭의 `내 기록` 항목 또는 종료 결과의 `내 기록` 버튼으로 목록을 엽니다. 최신 순으로 20개씩 표시하고 새로고침·더 보기·기록 상세를 제공합니다. 기록을 누르면 전체 경로 지도와 출발·도착 표시를 볼 수 있습니다. 경로가 저장되지 않은 기존 기록에는 경로 없음 상태를 표시합니다. 홈 상단 바와 조회 반경 선택은 제거하고 주변 러너는 기본 반경 1km로 조회합니다.
완료 기록은 서버 요청 전에 기기의 SQLite 저장소에 먼저 보관합니다. 서버 연결 실패 시 결과에 `기기에 저장됨`, 목록과 상세에 `서버 저장 대기`를 표시하며 다음 러닝을 시작할 수 있습니다.
로그인 후 앱 시작·복귀, 목록 새로고침과 `저장 재시도`에서 미전송 기록을 복구합니다. 앱이 열려 있는 동안 연결 실패는 30초부터 최대 5분 간격으로 자동 재시도하며, 백그라운드에서는 새 재시도 요청을 시작하지 않습니다. 서버가 측정값·권한·설정 문제로 거부한 기록은 원본을 유지하고 자동 반복 전송은 중단합니다.
서버가 성공 응답을 보낸 뒤에만 기기의 대기 원본을 삭제합니다. 응답 중단·삭제 실패·앱 종료 후에도 동일한 식별자와 측정값을 재전송하여 서버의 사용자별 중복 방지를 사용합니다.
보관 기록은 서버 주소와 계정별로 분리합니다. 로그아웃 시 원본은 보존하고 같은 계정으로 다시 로그인해야 조회·전송합니다. 저장소에는 완료 시각·거리·시간·기록 식별자와 구간별 위도·경도를 보관하며 인증 토큰이나 위치 정확도·좌표별 시각은 저장하지 않습니다. 저장소는 Android·iOS 앱 전용 영역을 사용하며 별도 데이터베이스 암호화는 적용하지 않습니다. 기록과 경로가 서버에서 함께 확정된 뒤에만 전송 대기 원본을 삭제합니다.
기기 저장 자체가 실패하면 종료 결과를 메모리에 유지하고 홈의 `저장 재시도`로 다시 저장해야 합니다. 이때 앱을 종료하면 결과를 잃을 수 있습니다. 진행 중인 러닝의 강제 종료 복구와 전체 서버 기록의 오프라인 캐시는 포함되지 않습니다. 앱 삭제 또는 기기 데이터 삭제 시 기기에만 남은 기록은 복구할 수 없습니다.
서버 경로는 상세를 열 때만 조회하며 친구나 다른 사용자에게 공개하지 않습니다. 전송 대기 기록의 경로는 오프라인에서도 볼 수 있지만 지도 배경은 연결 또는 타일 캐시가 필요합니다. 서버 저장을 마친 경로의 오프라인 캐시는 포함되지 않습니다. 서버 검증 전 측정값은 랭킹이나 공개 게시물로 자동 반영하지 않습니다. 러닝 초대·수락은 아직 포함되지 않습니다.

## 러닝 환경

홈의 지도 아래에는 기온·강수 상태·초미세먼지 참고 등급과 `양호`, `주의`, `자제`, `판단 불가` 상태를 표시합니다. 오른쪽 상세 버튼으로 바람·미세먼지 두 항목의 원래 관측 농도·측정소 거리·관측 시각·출처를 확인합니다. 보안등과 코스 추천은 반영하지 않습니다.

기상청 초단기실황과 한국환경공단 에어코리아 관측 자료를 Supabase `running-conditions` 함수에서 조회합니다. 인증키는 서버의 `KMA_SERVICE_KEY`, `AIRKOREA_SERVICE_KEY`에만 등록하며 앱 기능은 공공데이터 키를 참조하지 않습니다. 기상청 단기예보·에어코리아 대기오염정보·에어코리아 측정소정보 서비스의 활용 승인이 모두 필요합니다. 서버 설치와 검증 명령은 `supabase/README.md`를 참고합니다.

앱은 약 1km로 반올림한 위치만 서버에 보내며 외부 기관에는 기상청 5km 격자 또는 측정소 이름만 전송합니다. 위치를 환경 조회 이력으로 저장하지 않습니다. 두 미세먼지 항목을 측정하는 가장 가까운 측정소를 선택하되 30km를 넘으면 자료 없음으로 표시합니다. 국내 제공 범위 외에는 지원하지 않습니다.

홈이 보이는 동안 5분 주기로 서버 자료를 확인하며 위치 구역 변경 시 자동 조회합니다. 자동 재조회는 1분, 수동 재조회는 10초 이상 간격을 둡니다. 외부 API는 사용자마다 호출하지 않습니다. 날씨는 같은 5km 격자·발표 시각의 자료를 공동 사용하고, 미세먼지는 시·도 측정소 자료를 한꺼번에 받아 한 시간 동안 공유합니다. 현재 위치에는 가장 가까운 측정소의 농도를 표시하며 지역 평균으로 대체하지 않습니다. 조회 요청이 없는 지역은 갱신하지 않습니다.

서버 전체에서 기관별 최근 24시간 최대 450회의 외부 호출을 예약·집계합니다. 실패·시간 초과·추가 페이지도 포함하며 같은 지역 동시 요청은 하나의 갱신 작업만 수행합니다. 한도나 장애가 발생하면 마지막 정상 자료와 관측 시각·갱신 실패 안내를 표시합니다. 이 앱 서버 외부에서 같은 인증키를 사용하는 호출은 집계할 수 없으므로 키의 다른 사용처와 공공데이터포털 이용량도 확인해야 합니다.

다른 탭이나 백그라운드에서는 새 환경 조회를 시작하지 않으며 러닝 측정에는 영향을 주지 않습니다. 결측·기관 장애·공동 갱신 실패·관측 2시간 경과·잘못된 시각은 정상 자료로 대신하지 않고 전체 양호 판단을 중단합니다. 일부 정상 자료에서 주의 조건이 확인되면 해당 주의와 자료 누락을 함께 표시합니다.

기온 0°C 이하·30°C 이상, 풍속 8m/s 이상, 강수 관측은 앱 자체의 참고 주의 기준입니다. 두 미세먼지 농도 중 더 나쁜 참고 등급을 반영하며 매우 나쁨에는 야외 러닝 자제를 표시합니다. [에어코리아 농도 구간](https://m.airkorea.or.kr/info/behaviorInfo1)을 사용하지만 시간별 관측 농도의 참고 분류이며 공식 일평균 예보·특보나 건강 안전 보장이 아닙니다.

## 친구 관리

- 하단 `소셜`의 `친구`, `요청`, `검색` 탭에서 관리합니다. 기존 예시 랭킹은 `랭킹` 탭에 유지합니다.
- 친구 검색·요청·수락은 전화번호 인증과 닉네임 등록 후 가능합니다. 미인증 상태에서도 기존 개인 친구 목록 조회·요청 취소·거절·친구 삭제는 가능합니다.
- 검색은 정확한 닉네임 하나로 하며 영문 대소문자는 구분하지 않습니다. 본인, 신규 비공개 대상, 미인증·정지·양방향 차단 계정은 검색하지 않습니다. 검색과 요청 목록에는 이메일·전화번호·좌표를 반환하지 않습니다.
- 비공개 사용자가 공개된 상대에게 요청하면 그 상대에게 요청자의 닉네임이 표시됩니다. 친구 수락이나 삭제는 공개 설정과 위치 공유 스위치를 바꾸지 않습니다.
- 요청은 받은 사람만 수락·거절할 수 있습니다. 서로 요청해도 자동으로 수락하지 않으며, 이전 요청의 화면으로 새 요청을 취소하거나 수락하지 못하도록 관계 식별자를 검사합니다.
- 새 요청은 5초 간격, 계정당 한 시간에 30번으로 제한합니다. 친구와 양방향 대기 요청 합계는 계정당 최대 500개입니다. 취소·거절·삭제는 확인한 서버 상태를 기준으로 처리합니다.
- 소셜 화면을 열거나 앱으로 복귀할 때, 새로고침과 변경 후 서버 상태를 조회합니다. 소셜 화면이 열려 있는 동안 30초마다 갱신하며 백그라운드 조회와 푸시 알림은 포함하지 않습니다.
- 서버에는 `supabase/migrations/20261009100450_friend_management.sql`이 필요하며 연결된 RunSpot 프로젝트에 적용했습니다. 함께 달리기 초대는 친구 요청과 별개의 후속 기능입니다.

## 실행 방법

```sh
flutter run --dart-define-from-file=config/dev.json
```

`config/dev.json`에는 Supabase URL과 공개 키가 들어 있어야 합니다. 새 환경에서는 `config/example.json`을 복사해 실제 값을 채운 뒤 실행합니다.
디버그 IO 환경에서는 앱이 `config/dev.json`을 자동으로 보완 로딩하지만, 웹 실행이나 배포 빌드에서는 위 실행 옵션처럼 빌드 설정을 명시해야 합니다.
Supabase Auth의 Redirect URLs에는 `runspot://login-callback`을 등록해야 이메일 확인과 소셜 로그인이 앱으로 돌아옵니다.

## 지도와 위치 공유

- 지도는 `flutter_map`과 OpenStreetMap 타일을 사용합니다. 지도 API 키 없이 실행할 수 있습니다.
- 지도 배경은 밝은 저채도 색상으로 표시하며 내 위치와 러너 마커는 원래 색상을 유지합니다.
- 위치 공유는 기본으로 꺼져 있습니다. 공유를 켜려면 전화번호 인증, 닉네임 등록, 친구 또는 전체 공개 설정이 필요합니다.
- 서버에 `supabase/migrations/20261006000100_live_runner_map.sql`을 기존 마이그레이션 다음에 적용해야 주변 러너가 표시됩니다. 자세한 적용 안내는 `supabase/README.md`를 확인합니다.
- 기록 저장에는 `supabase/migrations/20261008000100_run_history.sql`을 적용해야 합니다. 기록은 전화번호 인증 여부와 관계없이 본인만 조회할 수 있습니다.
- 개인 경로 저장·조회에는 `supabase/migrations/20261009104713_private_run_routes.sql`도 적용해야 합니다. 기존 기록과 이전 버전 기기 저장소는 그대로 유지합니다.
- 앱이 백그라운드로 가거나 공유를 끄면 공유를 중단합니다. 다시 앱을 열어도 자동으로 공유를 켜지 않습니다.
- 이동 시 최대 5초 간격으로 전송하고, 정지 상태에서도 15초마다 현재 위치를 갱신합니다. 2분간 갱신되지 않은 위치는 조회에서 제외됩니다.
- 비공개 실시간 채널에는 좌표나 사용자 ID를 보내지 않습니다. 변경 신호 수신 후 서버 조회를 통해 현재 권한을 다시 확인합니다.
- 에뮬레이터는 테스트 위치를 설정해야 현재 위치를 찾을 수 있습니다. 실제 두 기기에서 공유·이동·비공개 전환을 확인해야 합니다.
- 타일 사용은 [OpenStreetMap 정책](https://operations.osmfoundation.org/policies/tiles/)을 따릅니다. 타일 공급자를 변경할 때에는 `MAP_TILE_URL`, `MAP_ATTRIBUTION`, `MAP_ATTRIBUTION_URL`을 빌드 설정으로 함께 지정합니다.

## 테스트 방법

### 화면 꺼짐 측정

- Android는 앱 화면에서 러닝 시작 후 위치 유형의 포그라운드 서비스와 지속 알림을 사용합니다. 러닝 중에만 부분 실행 잠금을 유지하며 화면 자체를 켜 두지는 않습니다.
- iOS는 앱 화면에서 시작한 GPS 구독을 백그라운드에서도 유지하고 시스템 위치 사용 표시를 켭니다. 지도만 보는 동안에는 백그라운드 측정을 허용하지 않습니다.
- 두 플랫폼 모두 사용 중 위치 권한으로 시작하며 항상 허용 권한은 요청하지 않습니다. 개인 측정 중에도 백그라운드에서는 위치 공유와 새로운 기록 업로드 재시도가 중단됩니다.
- 러닝 시작 준비 중 앱을 닫으면 시작을 취소합니다. 위치 오류로 정지한 측정은 앱 복귀만으로 자동 재개하지 않습니다.
- 앱 강제 종료·시스템의 프로세스 종료 뒤 진행 중인 측정 복구는 지원하지 않습니다. GPS가 30초 이상 끊긴 구간의 이동 거리도 추정해 더하지 않습니다.
- 실제 iPhone·Android에서 시작 → 화면 잠금 후 이동 → 잠금 해제 후 거리·시간 증가 → 일시 정지·종료 후 위치 표시·알림 해제를 확인해야 합니다. 공유를 켜고 같은 순서로 확인했을 때 잠금 이후 서버 위치 갱신이 없어야 합니다.

설정 근거: [Android 위치 권한](https://developer.android.com/develop/sensors-and-location/location/permissions), [포그라운드 서비스 시작 제한](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [iOS 사용 중 위치 권한](https://developer.apple.com/documentation/corelocation/cllocationmanager/requestwheninuseauthorization%28%29).

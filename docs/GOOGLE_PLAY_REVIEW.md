# 뜀터 구글 플레이 심사 준비

## 공개 정책 페이지

[웹 계정 삭제 요청](https://capstone-running-policy.web.app/account-deletion.html)은 공개되어 있습니다. 최종 방침을 게시할 때 이 페이지도 함께 빌드하면 방침 링크가 추가됩니다.

1. 공개할 원본은 [개인정보처리방침 HTML](../web/legal/privacy.html)입니다. 출시 기능이 달라지면 원본의 데이터 항목, 외부 처리업체, 보관 기간을 수정한 뒤 다시 게시합니다.
2. 기존 Firebase Hosting의 기본 주소는 `https://capstone-running-policy.web.app`입니다. 이 사이트를 사용하는 경우 두 페이지의 경로를 각각 `/privacy.html`, `/account-deletion.html`로 지정합니다. 출시용 설정에서 `PRIVACY_POLICY_URL`에 공개 `privacy.html` HTTPS 주소를, `ACCOUNT_DELETION_URL`에 공개 `account-deletion.html` HTTPS 주소를 입력합니다. `SUPPORT_EMAIL`에는 실제로 계정 삭제 요청을 처리할 운영 문의 주소를 입력합니다.
3. `python3 scripts/build_google_play_policy_pages.py config/prod.json <출력폴더> --privacy-html <최종방침.html>`로 두 페이지를 생성하고, 뜀터 운영 웹호스트의 위 주소에 게시합니다.
4. 로그아웃 상태의 브라우저에서 두 주소를 열어 앱 이름과 삭제 방법을 확인합니다. 출시 빌드에서는 **설정 → 개인정보처리방침**, **설정 → 웹에서 계정 삭제 요청**을 눌러 같은 페이지가 열리는지 확인합니다.
5. Play Console의 **앱 콘텐츠 → 개인정보처리방침**에는 방침 주소를, **데이터 보안 → 계정 삭제**에는 삭제 요청 주소를 입력합니다. 저장 후 콘솔에 표시된 주소도 로그아웃 브라우저에서 확인합니다.

신고 원문과 첨부 증빙은 신고 처리 또는 이의 제기 완료 후 90일이 지나면 예약 작업으로 파기하며, 신고 외에 참조가 없는 첨부 사진은 기존 운영 작업자가 저장소에서 제거합니다. 관리자 조치 및 탈퇴 감사기록은 처리 완료 후 180일이 지나면 예약 작업으로 파기합니다. 법정 보존이나 진행 중 분쟁에 해당하는 기록은 운영 데이터베이스 관리자가 보존 대상 행에만 `retention_hold_until`을 지정합니다. 종료일을 알 수 없는 동안에는 `infinity`로 지정하고, 사유가 종료되면 종료일로 바꿉니다. 실제 보존 근거와 증빙은 접근을 제한한 운영 기록에 별도로 남깁니다. 이 기준은 활성 제재 및 이의 제기 처리 상태에 적용하는 보관 기간과 별개입니다.

웹에서 이메일 요청이 접수되면 가입 이메일 또는 운영 승인 절차로 계정 소유권을 확인합니다. 비밀번호와 인증번호를 요청하지 않습니다. 계정 삭제 전에 Storage API에서 해당 계정의 게시판 첨부를 정리하고, 계정 삭제 후 연결 데이터의 파기와 예외적으로 보관되는 자료를 확인합니다. 처리 결과는 요청자에게 이메일로 안내합니다.

## 앱 액세스

운영 데이터와 분리한 심사용 일반 이메일 계정을 준비합니다. 이메일 인증, 로그인 후 운영정책 동의, 닉네임 입력을 완료하고 검토용 러닝 기록을 넣습니다. 운영 권한은 부여하지 않습니다. 새 Android 기기에서 로그인해 추가 인증 없이 접근할 수 있는지 확인합니다. 실제 이메일과 비밀번호는 **앱 콘텐츠 → 앱 액세스**의 로그인 입력란에만 보관합니다.

**접근 방법 입력문**

> 앱을 열고 이메일과 비밀번호를 입력한 뒤 ‘이메일로 로그인’을 누르세요. 안내된 계정은 이메일 인증을 마쳤으며 별도 인증 코드가 필요하지 않습니다. 러닝 기능은 홈에서 확인할 수 있습니다. 러닝 측정은 홈에서 시작하고 위치 권한을 허용하세요. 저장된 러닝의 상세 화면에서는 기록과 피드백을 확인할 수 있고, 게시판에서는 게시글·댓글과 신고 기능을 확인할 수 있습니다. 앱 설정에서 개인정보처리방침과 회원 탈퇴 경로를 확인할 수 있습니다.

계정의 접근 범위에 없는 기능은 해당 기능의 접근 방법을 별도로 등록합니다. 회원 탈퇴까지 실제로 검증해야 한다면 공용 심사 계정과 별도로 삭제할 수 있는 계정을 사용합니다.

## 심박 요약 전송

기본 러닝 피드백은 심박 자료 없이 요청할 수 있습니다. 사용자에게 전송 항목, 서버와 Google Gemini 전송, 생성 결과 저장을 표시하고, 요청마다 기본 해제된 별도 동의를 받습니다. 출시 전에 실제 Gemini 계약, 처리 및 보관 조건과 헬스 커넥트 정책을 대조합니다. 이 문서는 전송 허용이나 심사 승인을 확정하지 않습니다.

## 출시 등록과 비공개 테스트

- 첫 출시에는 인앱 결제를 사용하지 않습니다. `IN_APP_PAYMENTS_ENABLED` 기본값을 유지하고 출시 번들에서 현금 충전 경로가 보이지 않는지 확인합니다. 보상으로 받은 코인의 잔액·거래 내역과 코인 상점은 사용할 수 있습니다.

- 첫 앱 생성 시 표시 이름은 `뜀터`, 패키지 이름은 `com.runspot.runquest`, 기본 언어는 한국어, 유형은 앱, 다운로드 가격은 무료입니다. 계정 소유자가 정책·서명·수출 관련 선언을 확인하고 앱을 생성합니다.
- 앱 콘텐츠에서 개인정보처리방침, 앱 액세스, 데이터 보안, 타겟층, 콘텐츠 등급, 광고 여부, 건강 앱 및 권한 선언을 실제 번들과 맞춥니다. 러닝 사용 흐름을 기준으로 위치 포그라운드 서비스 설명과 시연 영상을 준비합니다.
- 신설 개인 개발자 계정 요건이 적용되면 비공개 테스트에서 최소 12명이 연속 14일 동안 참여 상태를 유지해야 합니다. 참여 인원과 의견, 반영 사항은 프로덕션 액세스 신청에 사용합니다. [구글 공식 비공개 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ko)
- 건강 데이터 외부 전송은 앱과 서버 양쪽의 `RUN_FEEDBACK_HEART_SHARING` 설정이 기본적으로 꺼져 있습니다. 전송 요건을 확인한 뒤에만 두 설정을 활성화합니다.

## 콘솔 답변과 시연 준비

| 콘솔 항목 | 제출 근거 |
| --- | --- |
| 건강 앱 | 활동 및 피트니스. 출시 번들의 헬스 커넥트 읽기 권한별로 운동 기록 가져오기, 심박·활동 칼로리 표시, 걸음 수 기반 케이던스 계산을 구분합니다. |
| 위치 포그라운드 서비스 | 러너가 직접 측정을 시작하면 알림을 표시하고 화면을 벗어나도 해당 러닝을 기록합니다. 종료한 뒤 기록과 알림이 멈추는 화면까지 시연합니다. 제출 번들의 병합 매니페스트에서 별도 백그라운드 위치 권한 포함 여부를 확인합니다. |
| 데이터 보안 | 계정 이메일·사용자 ID, 위치·러닝 기록·외부 운동 기록, 게시글·댓글·사진·메시지, 푸시 관련 식별자와 오류·진단 정보의 수집 및 전송 경로를 대조합니다. 심박을 기기에서만 표시하는 경로와 서버로 보내는 선택 경로를 구분합니다. 인앱 상품이 출시 빌드에서 동작하면 구매 내역과 결제 처리업체도 확인합니다. |
| 콘텐츠 등급과 타겟층 | 게시글·댓글·사진·사용자 메시지 기능을 포함해 설문에 답합니다. 출시 대상 연령과 플랫폼 분류는 운영팀 기준으로 확정합니다. |
| 앱 액세스 | 일반 심사 계정의 실제 접속을 확인하고 위의 안내와 자격 증명을 콘솔에 직접 저장합니다. |

## 첫 출시 전 추가 확인

- 첫 출시에는 기본 AI 피드백을 포함할 계획입니다. Gemini API 결제가 실제 서버 키의 프로젝트에서 활성화되어 있는지와, 서비스의 연령 정책이 API 이용약관을 충족하는지 확인합니다. 심박 요약 전송은 끈 상태를 유지합니다. [Gemini API 이용약관](https://ai.google.dev/gemini-api/terms)
- 위치기반서비스사업 신고 적용 여부를 관할 기관에 확인합니다. 적용 대상이면 위치 이용약관과 사전 동의, 제3자 제공 및 확인자료 보관 흐름을 출시 전 점검합니다. [위치정보법 제16조·제19조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029559495)
